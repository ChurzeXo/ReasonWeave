# 18 — 收尾才暴露问题（Shift-Left for Agents）

> 本章回答一个现象：**Agent 主线做得不错，但每次任务收尾都"顺带"冒出新问题**，用户感觉"每次做完都还有一件事"，"已完成"的可信度被稀释。本章是根因框架 + 对策；机件在 `~/Documents/lab/preflight/`，接入 playbook 既有章节见 §9。
> **状态**：由 `一期一卉花` 仓实战复盘收敛，经多 Agent 讨论 + 事实核验。非 AEF 原文派生，是 AEF 生态的补充。

## 1. 现象与定位

不是"粗心"，是一致的模式：Agent 先冲**显式请求**、验证后置。于是"完成"时刻天然晚于"请求完成"——收尾时才发现动手前就该发现的东西。

**Done 的定义错位**：Agent 的 Done = 显式请求完成；用户的 Done = 仓库回到自洽、没给我留新包袱。二者从未对齐。

## 2. 五条根因

| # | 根因 | 说明 |
|---|---|---|
| R1 | **Done 定义错位** | 见 §1；"完成"晚于"请求完成"。 |
| R2 | **存量/增量/已豁免 三分缺失** | 原二分（既有/我引入）缺第三类：**既有但已被显式决策豁免**（如 handoff 存量文档体积经 check 标"提示"非阻断）。二分法把"有出处的非问题"反复当新发现上报——正是"永远做不完"里那件不存在的事。 |
| R3 | **不变量无单一事实源** | git 跟踪态 / `.gitignore` / hooks / 跨文档约定散落多处，每个任务从零重新发现。 |
| R4 | **结论未验就上报**（最致命）| "我记得 / 应该是"被当"既有状态"说出。连待处理的问题本身都没经过 readback。 |
| R5 | **发现只有属地没有出口** | "既有 / 我引入"是**分类**不是**路由**——分完类没人把它变成 backlog id / 当场修复 / 豁免出处。分类不接路由 = 用户手里仍攥着散落包袱。 |

## 3. 一个必须记录的反转（为什么机器化不可妥协）

复盘时让另一个 Agent 做"事实核验"来质疑最初判断，结果**那个核验表本身几乎全错**——它把原本正确的陈述判成"幻觉"。实跑核验后，最初 5 条"发现"**全部真实**（部分已修、部分设计豁免），**零幻觉**；做复核的 Agent 用自带"核验"表把正确陈述判成幻觉，正是**同一条毛病在复核方身上重演**——它也没跑命令就下了否定结论。

**结论：连审慎的复核 Agent 都靠不住，靠"更小心"无解，必须机器化。** 且由此得一条护栏：**否定任何结论（含他人）前必须实跑命令核验，不凭印象。**

## 4. 对策：机器化（不是"更小心"）

把反复要人记住的约束落成**可跑命令 + 可机检的产出形状**：

| 对策 | 落到哪 |
|---|---|
| **可跑探针**（单一命令报出当前不变量态）| `preflight` 模块 `templates/preflight.sh`（类比 handoff check、Google presubmit）|
| **强制产出形状**（回报必含三节，存在性可机检）| `preflight` 模块 `templates/wrap-up.md` + 本手册 [12 章](12-gates.md) |
| **发现即路由**（每条有主）| 见 §5、[07 章](07-backlog.md) |
| **门禁挂到模型动不了的地方** | `preflight` 模块 `templates/pre-commit` + 宿主 Stop hook，见 §7 |

**关键纪律**：形状强制 > 思考强制。要求回报里**存在**指定三节（像 `handoff check` 硬校验锚节），"填空"这个动作本身迫使命题思考，比"养成习惯"可靠。

## 5. 三档判定（按波及面，不按 diff 大小）

改一行 `.gitignore` 会影响此后每次 `git add`（爆炸半径大）；新增独立文件的 300 行改动不碰任何共享面。判据 = **本次改动的 surface 是否与不变量集合相交**：

| 档 | 触发 | 动作 |
|---|---|---|
| **T0 跳过** | 只碰新文件 / 纯内容 | 直接做，一句话 diff |
| **T1 轻扫** | 改已跟踪的既有文件 | 跑廉价探针（`git status` / `ls-files` / `wc -l`）|
| **T2 全扫** | 触共享不变量面（`.gitignore` / `.gitattributes` / hooks / 分支与文件布局 / 带预算根文档 / 跨仓契约 `group/contracts` + `.handoffs`）| 全 `preflight` + 逐面点名 + 封闭核验清单 |

## 6. 三分法（发现分类 + 路由）

每条"非请求发现"归入其一，并**立即路由**：

- **既有**（继承债务，HEAD 中已存在且不在本次 diff）→ 入 backlog / 登记待拍板，**给 id**。
- **我引入**（本次改动产生）→ 当场修，或明确"为何暂不修"。
- **已豁免**（有显式出处，非问题）→ 标出处，**不是待办**。

判定归属**靠 git 不靠内省**（`git diff HEAD` / `status` / `log`，不是记忆）。
"我引入但可预测"的二阶后果：凡 diff 触及分支/文件布局，必须重跑 `git status --ignored` 并断言无运行产物变为可跟踪。

## 7. 收尾 DoD（D1–D7，本仓落地可推广）

- **D1** 请求已满足且有可跑的验证通过（evidence，[11 章](11-evidence.md)）。
- **D2** 工作树已交代：`git status --porcelain` 为空，或每个脏路径在回报中被点名 + 分类。
- **D3** 共享面已枚举：若有触碰，逐面列 `触点: 是/否`。
- **D4** 不变量探针全绿：`preflight.sh` 覆盖运行产物忽略 + 预算 + backlog 格式。
- **D5** 发现已路由：每条非请求发现归入 既有→backlog id / 已豁免→出处 / 我引入→当场修。无未分类散项。
- **D6** 回报形状：含 [`## 变动分类` + `## 不变量触点` + `## 遗留与路由`](12-gates.md) 三节（可机检存在性）。
- **D7** 无主散项：任何真遗留都有主（backlog id / handoff id / 显式"待人类拍板"行）。**D5+D7 是"你永远没做完"的正解**——把"还有一件事"变成"一件事已记录并派了主"。

## 8. 门禁执行与社区对照

**门禁必须挂到模型动不了的地方**——prompt 里写"记得验证"是**请求**，hook/CI 才是**法律**（模型无投票权）：

| 依据 | 要点 |
|---|---|
| Google Cloud *presubmit / global presubmit* | 不变量应落成**可跑命令**并在提交时强制，不是放 Agent 脑子里 |
| "Prompts are requests, hooks are law" | Stop/PreToolUse hook + exit code 是物理强制；prompt 无 observability |
| *Looping Is Not Reliability*（2026）| 纯自报通过率 99.8% 但风险 29.5%；加一个可见 gate 风险降到 2.4% |
| Self-Correction Blind Spot | 同模型自审约 64.5% 盲区 → 语义复核**必须独立上下文/跨模型** |
| Gary Klein *Pre-mortem* | "已惨败，回头看是什么导致的"提升失效识别约 30%；但本生态用**封闭核验清单** > 自由 pre-mortem |

**封闭核验 > 开放生成**：LLM 无人类式乐观偏见，开放生成召回差；有效做法是"强制逐面填 `触点:是/否 + 理由`"。

## 9. 反过度工程 & 落地动作

**采纳顺序**：先发**纯增量、零风险**的探针 + 回报形状，跑一轮看是否被流量用到，再决定是否加码；T0/T1/T2 先当**心智模型**，别急着写进脚本。一句话能描述 diff 的改动不必预研——over-planning 本身也是反模式。

**落地动作**：
1. 按 `~/Documents/lab/preflight/README.md` 接入：`preflight.sh` + `pre-commit` + `wrap-up.md` 三件套（[12 章](12-gates.md) 补三节门禁）。
2. [11 章](11-evidence.md) 加一条：**findings 进回报前必跑命令**（R4 的 readback）。
3. [07 章](07-backlog.md) 路由表补第三类「已豁免→出处」。
4. 门禁先从 L1（Agent 自查 + 出表）起步，成熟后升级到 hook/CI。
5. 语义层（"分类对不对""算不算真问题"）脚本不做——交回报形状 + 独立上下文复核。
