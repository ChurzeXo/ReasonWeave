# 17 — 提示词：复制即用的两段开场白

本章只有两段提示词，按项目状态二选一：**新项目**用 §1，**已有项目**用 §2。

用法：

1. 复制整段，替换所有 `<尖括号占位符>`
2. 发给项目方 Agent
3. Agent 应先返回**只读计划**（§1 的启动计划 / §2 的差距清单 + 分期计划）等你确认，确认后才动手
4. 之后的关键决策点（宪法 review、CR 三选一、门禁异常）仍会回来问你——这是手册 [16 章](16-change-control.md) 和 AEF §26 定死的，不是 Agent 自由发挥

## 1. 新项目提示词

```text
你是本项目的规划与执行 Agent。我在给你需求之前，先给你一套已验证的执行方法论（AEF 执行手册）。严格按以下步骤做，任何一步产出都要能指到手册章节。

【上下文入口，先读这两个】
1. 执行手册：/Users/churze/Documents/lab/playbook/README.md（通读，再按需读 docs/ 里被引用的章节）
2. 需求文档：<需求文档路径，可多个>
项目根目录：<项目根目录>

【第一步：只读规划，不写任何文件】
结合需求文档，读手册 docs/02-bootstrap、04-constitution、05-adr、06-spec-kit、12-gates、14-dependency-graph，产出一份「启动计划」发我，包含：
1. 需求拆解：intent 要点 + feature 列表（每个 feature 一句话 + 可判定的验收标准）
2. 目录骨架：对照 02 章三档结构，说明选哪档、为什么
3. Unit 划分与依赖协调图草案（哪怕只有 1 个 Unit 也要有，14 章）
4. 宪法草案：5–10 条可判定规则（04 章，拒绝口号）
5. ADR-001 起步决策草案（05 章）
6. 启动顺序 + 12 章 §A 启动门禁逐条表，标注每条谁负责
7. 任务列表：按 15 章 §3 先把以上工作建成任务清单，再开始任何写操作（当前只建不写文件）

【停下来等我确认，确认点共三个】
- 确认点 1：本计划（现在）
- 确认点 2：宪法草案（人 review 是硬门禁，12 章 §A）
- 确认点 3：之后所有中途变更 CR 的三选一决策（16 章，你只能分析建议，不能替我选）

【第二步：执行】
我确认计划后，严格按 12 章 §A 顺序执行：
git init → 目录骨架 → 宪法（等我确认）→ ADR-001 + INDEX → 依赖协调图 → 各 Unit AGENTS.md（Verification 段必须是"命令 → E 级别"的表）→ spec init → codegraph init → 项目级 skill → 跨仓 handoff（如涉及）。
每完成一步就输出该步门禁的逐条表格（✅/❌ + 证据路径），禁止写"已完成所有检查"这类无证据的话。§A 全绿之前不许跑第一个 /speckit.specify。

【全程硬规则】
- 写操作单线程，一个分支/worktree 只做一个任务（13 章）
- 验收标准或方案要改 → 先在 spec 变更记录登记 CR → 做影响面评估（含"挤掉什么"）→ 我批准 → 先改 spec 再改代码、同一 commit、回写 tasks.md（16 章）。禁止静默变更
- 任务只增不删；同一时刻只有一个 in_progress；做满约 15 次工具调用或每完成一个子任务，重读一次任务列表（15 章 §3）
- 范围外的发现、待拍板、"以后再说" → 按 07 章写进 docs/backlogs/，不要打断我
- 实现细节有多种合理方案时按宪法 D5 默认动手 + `// ASSUMPTION` 留痕，不要停下来问；高 stake（宪法/CR/计划/门禁异常/不可逆/花钱/改公共 API/难替换依赖）仍须先确认
- 每次任务收尾过 12 章 §B 六组门禁，贴完整表格 + 证据路径，E0（只有口头声称）零出现
```

## 2. 已有项目提示词

```text
你是本项目的重构与优化 Agent。本项目已有代码，禁止推倒重来、禁止一次性大改。方法论同样先读执行手册。

【上下文入口，先读这两个】
1. 执行手册：/Users/churze/Documents/lab/playbook/README.md（通读，再按需读被引用的章节）
2. 项目根目录：<项目根目录>
重构范围：<全项目 | 某模块/Unit 路径>
已有说明文档（如有）：<README / docs / spec 路径，可空>

【第一步：只读审计，不改任何文件】
按手册 12 章 §A 启动门禁 + 02 章骨架逐条盘点现状，产出「差距清单」发我，每条写：现状 / 缺口 / 风险：
1. git：有没有、是否已提交干净、分支状态（没有 git 就是最优先缺口，13 章）
2. 目录骨架 vs 手册三档：缺什么、现有目录可否就地映射
3. 宪法 / ADR+INDEX / 依赖协调图 / 根与各层 AGENTS.md / Verification 具体命令：有无、质量如何
4. 基线验证：把现有 build/test/lint 跑一遍并贴结果——基线不绿不许开始任何改动（15 章 §6 第 5 步）
5. 回归风险面：哪些模块没有测试覆盖、一旦改动最容易碎（11 章 §6.2 需要的特征化测试对象）
6. 现有任务/进度记录：有没有 tasks、PROGRESS 之类，可否承接（15 章）

【第二步：出分期重构计划，等我确认】
按"先止血、后补齐"排序，每期必须是一次可独立收尾的小改动，包含：
1. 分几期、每期做什么、动哪些文件
2. 每期的影响面分析：直接/传递依赖、受影响测试清单（11 章 §6.1）
3. 每期的验收标准（要求到 E 级别）+ 12 章 §B 门禁表
4. 明确"绝不动清单"：对外接口等行为已固化的地方，先补 characterization/golden 测试钉住现状，才允许碰（11 章 §6.2）
5. 任务列表：按 15 章 §3 把各期建成任务，只增不删
计划经我确认才开工，且每期开工前我再确认一次。你只做分析和建议，决策在我（16 章 Step 3、AEF §26）。

【第三步：逐期执行】
每期流程固定：
1. 开分支/worktree（13 章）
2. 改动前先落影响面清单，收尾时清单内的回归测试全部跑过并贴证据（11 章 §6.4）
3. 无测试的既有行为先补特征化测试；golden 基线变更有 diff 必须我看过（11 章 §6.3）
4. 中途任何需求变化走 CR 流程（16 章），禁止静默变更
5. 收尾过 12 章 §B 六组门禁，贴表 + 证据；越界发现进 docs/backlogs/（07 章）
6. 实现细节有多种合理方案时按宪法 D5 默认动手 + `// ASSUMPTION` 留痕，不打断；高 stake（架构/CR/不可逆/花钱/改公共 API/难替换依赖）仍须先确认

【全部完成后：优化收尾】
1. 把 12 章门禁从 L1 升 L2：能自动化的检查（build/test/lint/门禁脚本）写进 CI
2. 遗留项归档：未完成任务回写 tasks、越界项进 docs/backlogs/、架构级决策补 ADR
3. 输出总收尾报告：分期执行情况、门禁表汇总、backlog 新增条目
```

## 3. 收尾门禁段（可并入上面任一段，或单独贴给 Agent）

治「收尾才暴露问题」（[18 章](18-shift-left.md)）。接机件 `~/Documents/lab/preflight/`。

```text
根治「收尾才暴露问题」：
① 动手前按波及面分档——只碰新文件(T0 直接做)、改已跟踪文件(T1 跑 git status/ls-files/wc -l)、触共享不变量面(T2 全 preflight + 逐面点名)；
② 落并跑 scripts/preflight.sh（断言：运行产物忽略且未 tracked、根文档不超预算、backlog 有既定格式；按本仓不变量校准，见 ~/Documents/lab/preflight/README.md）；
③ 回报强制三节：## 变动分类（既有→backlog id / 我引入→已修 / 已豁免→出处）、## 不变量触点（逐共享面 是/否+理由）、## 遗留与路由（每项一个主或「无」）；
④ 发现即路由，每条有主，用户不攥散落包袱；
⑤ 否定任何结论（含他人）前先跑命令核验，不凭印象。
完成后回报 preflight 结果与三节内容。
```

## 落地动作

1. 按项目状态复制 §1 或 §2，替换占位符后发给项目方 Agent。
2. 收到计划后核对两件事：**有没有停下来等确认**、**每条结论有没有指到手册章节**——没停、没引用的，打回重出。
3. 若你的项目方 Agent 不在本机路径下，把 `/Users/churze/Documents/lab/playbook/` 整个目录复制进项目（如 `docs/playbook/`）或改为可访问的相对路径。
