## 3. 重要性水平与发现分级

**重要性判定口径**——以下任一成立即为 **P0（重大）**，审计意见不得优于「否定」：

- **P0 控制失效**：伪回执（声称的路径/提交不存在或与实际不符）能穿过 `receipt`/`accept`/`check` 任一处门禁；
- **P0 误伤阻断**：合规回执/交接被硬拦且**无合规绕过路径**（如无 env 豁免、无法补字段）；
- **P0 数据损毁**：`install` 静默删改载体非桩内容、或部分写入后崩溃留下半截文件；
- **P0 越权**：跨仓/跨目录写入到 hub 与全局载体之外的文件。

- **P1（中等）**：单分支控制失效但存在旁路或影响面小；文档与实现矛盾且 agent 照做会做错；未捕获异常导致流程中断。
- **P2（轻微）**：措辞、可维护性、性能、观察项、命名不一致。

> 每条发现必须标注：严重度 + **是否改 `STUB_BODY`**（改则 `STUB_SHA` 变 → 20 载体需重刷 → 下游 5 仓需 `install`）。这一项直接决定修复的连锁成本，不得省略。

## 4. 风险导向的审计策略

### 4.1 固有风险高地（按风险排序，程序资源优先投放）
1. **门禁互噬**：修 A 门禁时击穿 B 门禁（已发生过两次）→ Tier B 重点。
2. **evidence 只验「存在性」不验「相关性」**：声明真实但无关的路径即可过 → 红队第 1、2 项。
3. **跨仓降级分支被用作洗白通道**：不声明 `evidence_repo` 即可跳过硬核 → 红队第 2 项。
4. **单一源漂移**：契约改一处漏五处 → Tier D。
5. **存量豁免被打破**：新门禁误打到历史回执 → Tier E。
6. **桩系统静默失效**（v2.11.1 事故原型）→ Tier C。

### 4.2 程序组合
穿行测试（walkthrough）→ 控制测试（Tier A/B/C）→ 实质性程序（Tier D/E 抽样）→ 舞弊测试（§9 红队）。

### 4.3 抽样方案（ISA 530）
- **门禁类**：由 `check` 机器判定 ⇒ **100% 全量**（114/111 全覆盖），审计员做「反例注入」验证门禁真的会响。
- **存量正文质量类**：等距抽样 **20 份**（按文件名排序取模，抽样清单须写进工作底稿以便复核）。
- **高风险子集 100% 全查**：`date ≥ 2026-10-14`（evidence 生效日起）的全部回执 + 所有 `mode: intra-repo` 的回执。
- **交接正文「验收判据」可读性**：抽 **15 份**（2026-10 内优先）。

## 7. 证据标准与可靠性等级（ISA 500 本地化）

| 等级 | 来源 | 采信规则 |
|---|---|---|
| **L1** | 审计员亲自复现：命令 + 关键输出 + exit code（完整副本内） | 可单独支撑结论 |
| **L2** | 源码静态阅读（符号、行号、分支） | 须与 L1 互证；单独不足以判 PASS |
| **L3** | 文档声称（本文档、CHANGELOG、README、修复方说明） | **不可采信为结论**，只作「应然」对照 |

- 每条判据必须给：**命令 → 输出 → exit code**。**无证据视为未做**。
- 无法在本环境复现 ⇒ 标 `BLOCKED` + 原因，**不得臆断通过**。
- 严禁「我以为 / 应该没问题」。

## 8. 红队（舞弊与绕过测试 · 至少完成下列）

1. **相关性绕过**：构造「frontmatter 齐全 + 锚节齐全 + 转递提示词齐全 + evidence 声明**真实存在但与此任务无关**的路径/提交」→ 能否过全部三处门禁？判定这是**已知设计边界**还是缺陷，并给建议。
2. **降级分支洗白**：跨仓回执故意**不声明** `evidence_repo` 且塞一个**不存在**的提交 → 是否因降级而放行？若是，评估严重度（这是 B-4 的阴暗面，重点）。
3. **阈值穿越**：`date` 分别取 `2026-10-13` / `2026-10-14` / 缺失 / 未来日期 / 非 ISO 串 → 门禁是否被绕过。
4. **字段注入**：`evidence_paths` 填 `../../etc/passwd`、绝对路径、空串、超长串 → 是否被核验 / 是否越权读取 / 是否崩溃。
5. **篡改即报**：20 载体中抽 ≥5 件各改 1 字节 → `check` 必 exit≠0。
6. **sha 篡改**：只改 `stub:sha256:` 值（正文不动）→ 必报。
7. **cwd 越权**：从非 hub 目录跑 `install`/`check` → 绝不改动 hub / 全局载体以外的文件。
